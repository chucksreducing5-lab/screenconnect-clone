Add real native Windows Customer Agent (screen capture + input injection)

Root cause: all three native projects (Agent/Host/Service) compiled the
same Program.cs, which only implemented the technician Host Viewer. The
customer-facing agent had no real desktop capture (no BitBlt/CopyFromScreen)
and no real input injection (no SendInput/keybd_event) anywhere in the repo
- explaining reported symptoms of "most keys not working" and "image
quality never HD" when testing with the downloaded native app.

Changes:
- Restructure native-agent/native-host/native-service into their own
  directories (matching AGENTS.md's documented architecture and server.js's
  existing agentPublishDir/hostPublishDir expectations).
- native-agent/: brand-new real Customer Agent implementation
  - ScreenCapture.cs: real full-desktop capture via CopyFromScreen with
    adaptive JPEG quality tiers (Retina/1440p, Ultra/1080p, High, Medium,
    Low, Minimal), mirroring the browser's existing tier system.
  - InputInjector.cs: real Win32 SendInput-based keyboard/mouse injection.
    Resolves DOM code (layout independent) to VK codes first, covering
    letters, digits, F-keys, numpad, L/R modifiers, and all OEM punctuation
    keys (Period, Slash, Semicolon, BracketLeft, etc) - exactly the keys
    reported as "not working" - plus key-based and char-based fallbacks.
  - NativeMethods.cs: Win32 P/Invoke surface (SendInput, GetKeyState,
    BlockInput, GetSystemMetrics, SetProcessDpiAwareness, structs/consts).
  - AgentTrayContext.cs: system-tray runtime wiring capture + injection +
    WebSocket together; connects as role=customer&client=windows-native-agent
    (previously would have wrongly reused role=agent from the shared
    Program.cs); adaptive bandwidth-based tier upgrade/downgrade; releases
    held keys on disconnect to avoid stuck-key bugs.
  - Program.cs: entry point, launch-link resolution via
    /api/agent-launch/{id} with the customer token, per-monitor DPI
    awareness for accurate capture/coordinate mapping.
- native-service/Program.cs: new minimal watchdog/launcher (previously this
  project had zero source of its own) - starts and monitors
  RemoteSupportAgent.exe, restarting it on crash/exit.
- native-agent/RemoteSupportAgent.csproj: drop unnecessary/unsupported
  System.Net.WebSockets.Client 4.3.2 NuGet reference (ClientWebSocket ships
  in the net8.0-windows shared framework already).
- server.js: add windows-native-agent clientKind branch so the session is
  only marked live once a real screen.frame arrives, not on socket connect
  (consistent with existing Android/iOS broadcast handling).
- FIX_NATIVE_AGENT.md: documents root cause, fix, and required build steps.

Note: this sandbox has no .NET SDK, so this code could not be compiled or
tested here - it was carefully hand-verified (brace/paren balance, and
cross-checked against the existing working Host Viewer patterns for
WebSocket reconnect, launch-data decoding, DPI handling). Someone with a
Windows machine or CI needs to run dotnet publish for native-agent,
native-host, and native-service and deploy the publish/ output.
